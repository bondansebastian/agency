# Troubleshooting

- **Requirements:** Node 20 or newer, ffmpeg on the PATH (Windows: `winget install Gyan.FFmpeg`; Linux: `apt install ffmpeg`), Playwright with Chromium and Playwright's own ffmpeg (`npx playwright install chromium ffmpeg`).
- **The recording is empty, no error:** the Playwright version and its downloaded browser builds do not match. Install the matching browsers, or point `DOCS_PLAYWRIGHT` at another Playwright install's `index.js` and `DOCS_CHROMIUM` at a browser executable. Check with a 3-second test recording first.
- **Overlay text has no style / captions are plain:** the app has a strict CSP that drops `<style>` elements and `style=""` attributes in injected HTML. `lib.mjs` uses a constructable stylesheet and classes (`k-*`). Style any new card with classes added to that stylesheet, never inline.
- **A caption disappears behind a dialog:** native `<dialog>` is in the top layer. The overlay uses popovers and re-shows them on every helper call; call a helper (for example `rec.caption`) after a dialog opens.
- **Clicks time out with "intercepts pointer events":** the overlay must have `pointer-events:none` (it does in `lib.mjs`); do not add overlay elements without it.
- **A native `<select>` list is not visible in the video:** headless Chromium does not draw it. Move the cursor to it, use `selectOption`, and explain the choice in a caption.
- **The app server does not start:** pass `--serve` with the exact command and `--url` with the address it prints. The runner waits up to 2 minutes and stops the server afterwards.
- **An earlier video, or its copies and contact sheets, vanished:** every run empties its output folder first (`--out`, default `out/` beside the scenario): `startRecording()` in `lib.mjs` deletes the whole folder, not only that video's files, because it then picks up the one `.webm` Playwright writes there. Recording several videos into the same folder therefore keeps only the last one, along with anything else you saved there (a compressed upload copy, contact sheets, notes). Record one video at a time and move or upload each result (the mp4, any smaller upload copy, the contact sheets) before starting the next run, or give each run its own `--out` folder. Never point `--out` at a folder that holds anything you want to keep. A wrapper script that calls the recorder (a project's `record.sh`) has the same effect.
- **After the app changed:** re-run the same scenario. Edit it only where a label, a button or the flow changed; update the sample data first if the preview must show new behaviour.
- **`--music` fails or the video is silent:** music needs ffmpeg and ffprobe on the PATH and an audio file, from the `music` field of the extension's `brand.json` or `--music`. Without either the video is silent by design. A video longer than the bed loops it, with a small seam.
- **The credit, cover look or music is missing:** the extension was not passed. Add `--brand <counterpart folder>/brand.json` (or set `DOCS_BRAND` to that path), where the folder is the one shown when the extension counterpart skill loads. If no counterpart is installed, the neutral look is correct.
- **The project's `lib.mjs` or `record.mjs` is an older copy** (it has a built-in credit, reads `IGNIS_*` variables, or has no `--brand` flag): replace both with this skill's `scripts/lib.mjs` and `scripts/record.mjs`. Scenarios need no change. Rename `IGNIS_PLAYWRIGHT`, `IGNIS_CHROMIUM` and `IGNIS_STORAGE_STATE` to `DOCS_PLAYWRIGHT`, `DOCS_CHROMIUM` and `DOCS_STORAGE_STATE`, and pass the brand with `--brand` or `DOCS_BRAND`.
